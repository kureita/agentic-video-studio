Asset Node — Code Analysis

Upload flows for image & video via canvas tool node and AI assistant
March 9, 2026
Overview

The mediaUpload node handles user-uploaded assets (images, videos, audio). Two entry points exist:

  • Canvas tool node — user adds node via toolbar, then uploads a file directly.
  • AI assistant — user attaches files via paperclip or drag & drop; the agent creates mediaUpload nodes automatically.

Both paths use a single backend endpoint: POST /api/assets/upload, which delegates to LocalStorageService or S3StorageService based on the STORAGE_TYPE env var.

Image Upload
Local
User selects file → POST /api/assets/upload → saved to tmp/kureita_uploads/{uuid}.{ext} → URL: {api_base_url}/tmp_uploads/{uuid}.{ext} → served via StaticFiles mount
Production (S3)
User selects file → POST /api/assets/upload → uploaded to s3://{bucket}/uploads/{YYYY/MM/DD}/{uuid}.{ext} → raw URL returned → displayed via presigned GET URL

Working correctly in both environments.

Video Upload + Frame Extraction

Video upload follows the same path as images. After upload succeeds, the node auto-extracts start frame and end frame.

Client-side extraction (primary)
Upload completes → setTimeout 1s → extractFrameFromVideo(url, 0) → canvas toDataURL → base64 start frame → extractFrameFromVideo(url, 1) → canvas toDataURL → base64 end frame → POST /api/workflows/{id}/nodes/{nodeId}/extract-frames → backend decodes base64, saves via StorageService (local or S3) → stored as outputs.{nodeId}__start_frame / __end_frame in MongoDB
Server-side fallback (headless runs)
_resolve_inputs() checks outputs for {nodeId}__start_frame → if missing, falls back to ffmpeg/ffprobe extraction → downloads video → extracts frame → returns base64

Bug Fallback only triggers for videoGen nodes, not mediaUpload.

Partial — client path works, server fallback broken for mediaUpload.

AI Assistant (Attachment & Drag/Drop)
Paperclip / Drag & Drop
User attaches file (paperclip or drag&drop) → validated against allowlist (jpeg, png, webp, gif, mp4, webm, mov) → blob preview created → stored as pendingAttachment → on submit: uploaded to POST /api/assets/upload → message constructed: [Attached: file.mp4] (video/mp4) - URL: https://... → sent to agent → agent creates mediaUpload node with that URL

Working correctly. Upload, message format, and agent interpretation all consistent.

Issues Found
# Severity Area Description
1 Bug Server Frame extraction fallback in _resolve_inputs only checks videoGen — skips mediaUpload nodes entirely. Headless runs lose start/end frames.
2 Medium Prod Client frame extraction uses raw S3 URL with crossOrigin="anonymous". If S3 bucket CORS isn't configured, canvas is tainted and extraction fails silently.
3 Medium UX Agent sidebar rejects audio files (accept="image/*,video/*") but the canvas MediaUploadNode accepts audio/*. Inconsistent behavior.
4 Medium UX MediaUploadNode shows "Drag & drop or click to browse" but has zero drag/drop handlers. Only click works.
5 Medium Race extractFrames endpoint reads video URL from DB, but the auto-save may not have flushed yet (1s delay). Can return 400.
6 Medium Local CORS middleware covers /static paths but not /tmp_uploads. Local video frame extraction may fail with tainted canvas.
7 Low UX No upload progress indicator for large video files — only a boolean spinner.
8 Low Server _run_media_upload_node doesn't return frames (by design), making headless runs dependent on prior client extraction.
