High-Level System Architecture

Kureita is an AI-powered video production platform. Users provide a website URL or creative prompt, and the platform generates branded promotional videos using AI models for text, image, video, and audio generation. The final video is composed client-side using Remotion.

Frontend

Next.js 15 static export, hosted on AWS Amplify. Auth0 for login. XYFlow for workflow editor. Remotion for client-side video rendering.

Backend

FastAPI running on AWS Lambda via Lambda Web Adapter. Auth0 JWT validation. MongoDB Atlas for data. S3 for assets.

AI Stack

GPT-4o for brand analysis, story, script. Gemini for workflow agent, vision. Imagen 4 for images. Veo 3.1 for video. ElevenLabs for audio.

Infrastructure

SAM/CloudFormation deployment. ECR for Docker images. API Gateway v2 HTTP API. S3 for asset storage. Amplify for frontend.

Services Deep Dive

VideoGenerator

video_generator.py — Uses Google Veo 3.1 (veo-3.0-generate-preview). Supports text-to-video, image-to-video, reference images, frame interpolation, video extension. Mock mode returns placeholders from static/videos/. 720p/1080p, 4/6/8 sec.

ImageGenerator

image_generator.py — Uses Imagen 4 (imagen-4.0-generate-preview-05-20) or Gemini Flash multimodal. Supports reference image input. Mock mode returns placeholders from static/images/.

AudioGenerator

audio_generator.py — Uses ElevenLabs TTS API (eleven_multilingual_v2). Falls back to Google gTTS in mock/free mode. Multiple voice support.

EditorAgent

editor_agent.py — Uses Gemini to generate Remotion TSX composition code. Takes video/image/audio URLs + text instruction, outputs React component code. Frontend compiles via sucrase and renders with @remotion/player.

NodeRunner

node_runner.py (709 lines) — Central workflow execution engine. Dispatches nodes to correct service based on type. Resolves input dependencies via edge connections. Supports @Text #N prompt references.

GenerationPipeline

pipeline.py — Orchestrates full video gen: Analyze → Story → Script → Generate Assets → Compose. Runs as background task from POST /projects/{id}/start.

AgentService

agent_service.py — Uses Gemini 2.5 Flash to generate workflow structures (nodes + edges) from natural language prompts. Returns thinking process and tool calls.

StorageService

storage_service.py — Abstract base with LocalStorageService (static dir) and S3StorageService (boto3, date-organized uploads). Selected via STORAGE_TYPE env var.

WebScraper

scraper.py — httpx + BeautifulSoup4. Extracts title, meta, headings, main content, images, links, contact info, social links from any URL.

LLMService

llm.py — Unified LLM interface. Supports openai (GPT-4o) and gemini (2.5 Flash) providers. JSON response mode for OpenAI.

AI Agents (all use GPT-4o)

Agent File Input Output
BrandAnalyzer brand_analyzer.py Scraped website content + URL BrandProfile (name, tagline, colors, tone, products, USPs)
Storyteller storyteller.py BrandProfile + duration + style Story (title, synopsis, key messages, emotion, CTA)

Two Creation Modes

The platform offers two distinct ways to create videos:

Mode 1: Canvas Pipeline (Guided, Step-by-Step)

A linear, wizard-like flow where the user is guided through each stage. Best for users who want a simple, opinionated workflow.

sequenceDiagram
    actor User
    participant Canvas as Canvas UI
    participant API as Backend API
    participant AI as AI Services
    User->>Canvas: Enter website URL
    Canvas->>API: POST /canvas/create
    API->>AI: Scrape + BrandAnalyzer (GPT-4o)
    AI-->>API: BrandProfile
    API-->>Canvas: brand_profile + project_id
    User->>Canvas: Configure story options
    Canvas->>API: POST /canvas/{id}/story
    API->>AI: Storyteller + ScriptWriter (GPT-4o)
    AI-->>API: Story + Scenes[]
    API-->>Canvas: story + scenes
    User->>Canvas: Review, edit scenes, generate images
    Canvas->>API: POST /canvas/{id}/images
    API->>AI: ImageGenerator (Imagen 4)
    API-->>Canvas: scenes with image_url
    User->>Canvas: Generate videos
    Canvas->>API: POST /canvas/{id}/videos
    API->>AI: VideoGenerator (Veo 3.1)
    API-->>Canvas: scenes with video_url
    User->>Canvas: Compose final video
    Note over Canvas: Remotion renders client-side

Mode 2: Workflow Editor (Node-Based, Flexible)

A freeform node graph editor (like ComfyUI). Users connect nodes visually or use the AI chat agent to generate workflows. Best for power users who want full control.

Authentication Flow

Auth0 handles all authentication. The backend validates JWT tokens against Auth0's JWKS endpoint and auto-provisions users in MongoDB.

sequenceDiagram
    actor User
    participant Browser
    participant Auth0
    participant Frontend
    participant API
    User->>Browser: Visit app.kureita.com
    Browser->>Frontend: Load page
    Frontend->>Frontend: AuthGuard checks isAuthenticated
    alt Not authenticated
        Frontend->>Auth0: Redirect to Auth0 login
        Auth0->>User: Login/Signup form
        User->>Auth0: Credentials
        Auth0->>Browser: Redirect with auth code
        Browser->>Auth0: Exchange code for tokens
        Auth0-->>Browser: Access Token (JWT)
    end
    Frontend->>API: GET /api/me (Bearer token)
    API->>Auth0: Validate JWT via JWKS
    API->>API: get_or_create_user (MongoDB)
    API-->>Frontend: User profile

Key Implementation Details

Frontend Auth

AuthProvider wraps app with @auth0/auth0-react. AuthGuard protects routes. Token getter injected into Axios interceptor via setAuthTokenGetter().

Backend Auth

core/auth.py: Fetches JWKS from Auth0, validates JWT signature + audience + issuer. get_current_user dependency on all /api routes.

User Provisioning

core/user.py: get_or_create_user() looks up by auth0_sub. Creates new doc in users collection if first time. Returns user dict for downstream use.

Data Tenancy

All queries filter by user_id from the authenticated user. Legacy projects (no user_id) are visible via $or query fallback.

Key Maintainer Notes

API Gateway Timeout API Gateway has a hard 29-second timeout. Video generation with Veo 3.1 can take 60+ seconds. The start_generation endpoint uses FastAPI BackgroundTasks, but individual workflow node runs (POST /workflows/{id}/nodes/{nid}/run) are synchronous and may timeout for video gen nodes in production. Consider implementing WebSocket or polling pattern.
Playwright in Lambda WebScraper lists Playwright as a dependency in pyproject.toml, but browser install is commented out in the Dockerfile. Currently scraping uses httpx + BeautifulSoup (no JS rendering). If full JS rendering is needed, enable Playwright in container (significantly increases image size).
Mock Mode Set USE_MOCK_VEO=true for development. This makes all video/image generation return placeholder files from static/ directories with simulated delays, avoiding API costs. Audio mock uses free Google gTTS.
Remotion Rendering Video composition happens entirely client-side using @remotion/player and @remotion/web-renderer. The EditorAgent generates TSX code on the backend, which the frontend compiles using sucrase and renders in the browser. No server-side rendering infrastructure needed.
Data Storage Summary User accounts: MongoDB users (auto-provisioned). Projects: MongoDB projects (embedded brand, story, scenes). Workflows: MongoDB workflows (nodes, edges, outputs, chat). Generated media: S3 or static/uploads/. Remotion compositions: in-memory (frontend only). Auth tokens: browser memory. Canvas state: localStorage (Zustand persist).
